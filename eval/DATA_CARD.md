# DATA_CARD.md: Benchmark Dataset Card

## 1. Summary

A seeded, fully synthetic benchmark for lost-item retrieval, generated by `eval/generator.py`
(`generate_benchmark_dataset(seed=42)`). Nothing in it comes from real people.

| | |
| --- | --- |
| True items | 300 (25 per category × 12 categories), each with one lost report and one found report |
| Background | 100 found reports with no owner (unclaimed items), written like real found reports |
| Split | 30% development (90 items) / 70% test (210 items), stratified by category; every item carries its split label |
| Query and pool | Each lost report is a query; the pool is all found reports of its split plus the 100 background reports (190 for dev, 310 for test) |
| Ground truth | Exactly one correct found report per query |
| Content hashes | SHA-256 of each split, recorded in `results/frozen_config.json` and the results file |

## 2. How it is built

- **Text.** Each item has a category, a colour, a brand, and a distinguishing feature. The lost and
  found sides use different lexicons (e.g. "navy flask" vs "dark blue water bottle"), different
  sentence templates, each side drops one or two attributes at random, and about 2% of letters get
  a typo. Background reports use the found-side templates, so they cannot be spotted by wording.
- **Location.** A campus tree (5 buildings × 4 floors × 2 rooms = 40 leaves) with two pairs of
  adjacent buildings. The found location is the true room with probability 0.6, one level off
  (the floor instead of the room, or a sibling room) with 0.3, and anywhere on campus with 0.1.
- **Time.** Losses fall uniformly over 60 days. The owner reports an exact time (40%), a 5-hour
  period (40%) or the whole day (20%) containing the true time. The item is found after a
  log-normal delay with a median of 6 hours.
- **Scoring.** Location and time are scored with the application's own domain functions; text
  with the pinned all-MiniLM-L6-v2 model, offline.

## 3. What it does not contain

- **No photos.** The spec's real-photo subset (at least 60 items, each photographed twice by
  different people) has **not been collected**. So there are no images, no faces, no EXIF data,
  and no image results. The image system and the missing-photo sweep are reported as not evaluated.
- **No human-written text.** The spec's human-written subset (two people writing blind) has
  **not been collected**. All text is template-generated.
- **No consent records are needed or held**, because no contributor data exists. If the photo or
  human-written subsets are collected later, written consent and a licence for every photo must be
  recorded here before use, photos must be screened for faces, ID numbers and number plates, and
  EXIF must be removed.

## 4. Known biases and limits

- Location and time follow the same assumptions the scoring encodes, so their benefit in the
  benchmark is partly by construction (stated in `HYPOTHESES.md` before the test run).
- Because losses are spread over 60 days and items are found within hours, time alone separates
  most items; real campus reports cluster in term time and in a few popular buildings.
- Template text is cleaner and more regular than real reports.

## 5. Privacy

Contains no personal data, no real reports and no real user content. Real users' reports are
never used for evaluation (P7).
